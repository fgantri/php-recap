Your course notes say something worth repeating before anything else, because every lesson here is a piece of it:

The whole of web development

A browser sends text over a network to a program that is listening on a port. That program hands the text to PHP. PHP runs your code top to bottom, possibly asking a database for data, and produces more text. That text goes back over the network, and the browser draws it.

The course taught you that sentence. This weekend takes each noun in it — browser, text, network, program, listening, port, database, draws — and opens it up. That is the entire difference between knowing PHP and knowing the web.

Before Friday morning

Your machine has git, node, python and curl. It does not have PHP or a database — and you are going to install them one rung at a time, at the moment you need them, rather than as one opaque command.

That is deliberate. Being handed sudo apt install with six packages you can't justify is the same problem as being handed XAMPP: a bundle you operate without a model of what's inside it. So the first lesson is about the tools themselves.

One WSL quirk to know now

This workspace lives under /mnt/c/, which is the Windows filesystem seen through a translation layer. File permissions there are largely fictional and chmod often does nothing. When Lesson 0002 covers permissions, do that exercise in ~/ (the real Linux filesystem) instead. Your projects should live in ~/websites/ for the same reason — WSL is markedly faster there.

How to work through this

Type everything

Do not copy-paste. Your course said it and it is right: the muscle memory for <?php ?> only comes from typing it badly a hundred times. The same is true of socket_bind and PDO::FETCH_ASSOC.

Answer before revealing

Every lesson has retrieval prompts with a hidden answer. Say your answer out loud first. Recalling badly and then seeing the answer builds far more durable memory than reading a correct answer smoothly.

Break it on purpose

Where a lesson says "now make it fail", make it fail. Knowing the shape of a broken page — blank vs partial vs 500 — is a diagnostic skill you cannot get from working code.

Ask me anything

I am the teacher for this course, not just its author. When something is unclear, ask in the terminal — including "explain that again but for someone who knows JavaScript".
