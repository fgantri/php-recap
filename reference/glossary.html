Glossary

Every term this course uses, defined once. Where a word means different things in different worlds, both meanings are given — that ambiguity is usually the reason the word was confusing.

The machine

Process
A running instance of a program, with its own memory, file-descriptor table, working directory, environment and PID. Isolation between processes is enforced by the kernel. Lesson 0001.
fork / exec
fork() clones the current process; exec() replaces a process's memory with a different program while keeping its PID and open descriptors. Every command you run is a fork followed by an exec.
File descriptor
A small integer indexing the kernel's table of things this process has open. 0, 1 and 2 are stdin, stdout and stderr; files, pipes and sockets get the rest.
Environment
(1) A set of key–value strings attached to a process, inherited as a copy by children. (2) The software installed on your machine. (3) A deployment context — local, staging, production. The course uses all three; context disambiguates.
PATH
A colon-separated list of directories the shell searches, in order, for an executable matching a command name. First match wins. Version managers work purely by reordering it.
Builtin
A command implemented inside the shell rather than as a file on disk. cd, export and source must be builtins because a child process cannot change its parent's state.
Exit code
The integer a process returns when it dies. Zero means success; non-zero values distinguish failures. &&, || and every CI pipeline are built on it.
Inode
The structure holding everything about a file except its name — permissions, owner, size, timestamps, link count, and pointers to the data blocks. Names live in directories and point at inodes.
Hard link
An additional directory entry pointing at an existing inode. No name is "the original"; the data survives until the link count reaches zero and no process has it open.
Symbolic link
A small file whose contents are a path. Resolving it restarts the lookup. Deleting the target leaves a dangling link. The basis of atomic symlink deployments.
Document root
The directory a web server maps request paths into. Files above it are unreachable by URL, which is why frameworks put only public/ inside it. Lesson 0002, 0007.
Path traversal
Escaping the document root using .. or its encodings. Defence: resolve with realpath() and verify the result still begins with the root — never string-strip ...

The network

Socket
A file descriptor representing a network endpoint. Read and written with the same calls as a file.
Port
A number 0–65535 identifying which listening program on a machine a connection is for. Below 1024 requires root. Lesson 0004.
Four-tuple
(source IP, source port, destination IP, destination port) — what actually identifies a TCP connection, and why one server port can serve thousands of clients.
Accept loop
The structure of every TCP server: socket → bind → listen, then repeatedly accept. accept() returns a new socket per connection; the listening socket never carries data.
Backlog
The kernel's queue of connections accepted by the OS but not yet by your program. Fixed size; when full, new connections are refused.
Head-of-line blocking
One slow item delaying everything behind it. Visible in a single-worker server, and the problem HTTP/2 multiplexing was designed to reduce.
Event loop
One process handling many sockets by asking the kernel which are ready (epoll) and servicing only those. nginx, Node.js, Cloudflare Workers. Excellent for I/O, fatal if you block it.
HTTP
A text protocol: request line, headers, blank line, optional body. Lines end \r\n. Stateless by design. Lesson 0005.
Idempotent
Doing it N times leaves the same state as doing it once. What makes automatic retry safe. GET, PUT and DELETE promise it; POST does not.
Safe (method)
Changes nothing on the server. GET and HEAD. Breaking this promise is how crawlers delete your data.
Stateless
Each request is self-contained and the server remembers nothing between them. The constraint that makes load balancing, CDNs and edge compute possible.
TTL
How long a cached DNS record may be reused. Why DNS changes appear to take hours — nothing is "propagating"; old answers are expiring.
CGI / FastCGI / PHP-FPM
CGI (1993) spawned a process per request and passed the request as environment variables. FastCGI keeps processes alive over a persistent socket. PHP-FPM is PHP's FastCGI process manager. $_SERVER's key names are CGI's, unchanged. Lesson 0007.

PHP the engine

Opcode
One instruction in the array PHP compiles your source into. The VM executes these; the CPU never sees your PHP. Lesson 0008.
OPcache
Shared-memory cache of compiled opcodes, skipping lex/parse/compile on subsequent requests. With validate_timestamps=0 it must be reset on deploy.
Shared-nothing
Every request starts from zero state. The process may be reused; your program's world is not. Why sessions and caches exist, and what serverless rediscovered.
Parse error
Failure during phase 2, before any execution — so the whole page is blank, including output from correct lines above the mistake.
Runtime error
Failure during execution. Output produced before the failure still reaches the browser, which is why a partially rendered page points here.
zval
PHP's variable container: a type tag plus a value, or a pointer plus a reference count for strings, arrays and objects. Lesson 0009.
Copy-on-write
Assignment copies a pointer and increments a refcount; the data is duplicated only when one holder writes. Why passing large arrays is free until someone mutates.
Handle (object)
What an object variable holds — an identifier into the object store. Copied by value, but both copies designate one object. Not "by reference", though it is often miscalled that.
Ordered hash map
PHP's single array type, serving as both list and dictionary, preserving insertion order. Lesson 0011.
Packed array
Optimised layout used when keys are exactly 0..n−1: a flat contiguous block with no hashing. Broken by gaps; restored by array_values().
Truthy / falsy
The eight falsy values are false, 0, 0.0, -0.0, '', '0', [], null. Everything else is truthy. Lesson 0010.
Call stack / frame
The structure tracking where execution is. Each call pushes a frame holding parameters and locals; return pops it. A stack trace is a snapshot of the open frames.
Closure
An anonymous function that captures variables from its defining scope. PHP requires explicit capture with use (by value unless you write &); arrow functions capture automatically, by value.
Higher-order function
One that takes or returns a function. Owns the mechanism while the caller supplies the policy. Middleware, hooks, event listeners and route handlers are all this.
Output buffering
ob_start() / ob_get_clean() — intercepting output so it can be captured as a string. The mechanism every PHP template engine is built on. Lesson 0013.
Superglobal
A PHP-provided array visible in every scope: $_SERVER, $_GET, $_POST, $_SESSION, $_COOKIE, $_FILES, $_ENV, $_REQUEST. All but the last two are filled from client data — treat as hostile.
Throwable
The interface above both Error (engine problems) and Exception (your problems). They are siblings — catch (Exception) does not catch a TypeError.

Structure and patterns

Front controller
One entry point handling every request, which bootstraps and then dispatches. public/index.php in Laravel and Symfony. Made possible by the server's try_files fallback. Lesson 0014.
Router / dispatcher
Matches the request path (and method) against registered patterns and hands off to a handler. Patterns compile to anchored regular expressions with named capture groups.
Controller
Accepts a request, gathers data, makes decisions, and hands assembled data to a view. Contains logic, not markup.
View / template
Renders a response from data it was given. Contains markup, and no decisions. Keeping it "dumb" is the discipline that makes the separation pay.
Partial
A reusable fragment of a view. Blade's @include, Twig's {% include %}.
Layout
A shell template that a page's rendered content is injected into. Cleaner than head/footer partials because tags open and close in one file.
Bootstrap
The startup sequence: helpers → config → shared services → routes → dispatch. Every framework's entry point is these five steps.
Middleware
A layer wrapping the request/response cycle, receiving the request and the next handler. Structurally a chain of callbacks.
Dependency injection
A component declares what it needs (usually as constructor parameters) and a container supplies it — instead of reaching for shared globals. What makes code testable.
DRY
Don't Repeat Yourself: one authoritative representation per piece of knowledge. Counter-principle: extracting before you have seen enough cases produces bad abstractions. Duplicate once; extract on the third.
Refactoring
Changing structure without changing observable behaviour. Not an indulgence — the main activity after "it works".
Magic number
A bare literal whose meaning is implicit. Fixed by a named variable or a class constant.

Data

Primary key
Uniquely identifies a row; never null, never reused. Usually an AUTO_INCREMENT integer. What relationships are built on.
Foreign key
A column holding another table's primary key. With a constraint declared, the database refuses writes that would break the reference.
Referential integrity
The guarantee that every foreign key points at a row that exists. Enforced by the database, which no application bug can bypass.
Orphan record
A row whose foreign key points at something deleted. Damage is quiet: joins silently drop rows, reports undercount.
Cascade
What happens to dependent rows when a parent is deleted: CASCADE, RESTRICT, SET NULL, SET DEFAULT. A modelling decision, not a default.
Index
A sorted structure (usually a B-tree) over one or more columns, with pointers back to rows. Faster reads, slower writes, more disk. Lesson 0018.
Full table scan
Reading every row because no usable index exists. Fine on 100 rows, fatal on 10 million.
Declarative
You describe the result you want; the engine decides how. SQL is declarative; PHP is imperative. Why you never write a loop over rows in SQL.
DSN
Data Source Name — one string describing how to reach a database. mysql:host=localhost;port=3306;dbname=app;charset=utf8mb4.
Prepared statement
SQL sent to the database for parsing separately from its parameter values, so values can never be read as structure. The defence against SQL injection. Lesson 0020.
Transaction
A group of changes that either all apply or none do.
Soft delete
Marking a row deleted with a timestamp instead of removing it. Reversible and audit-friendly; every query must then remember to exclude them.
utf8mb4
MySQL's real UTF-8. Its utf8 stores only three bytes per character and cannot hold emoji or some CJK text. Always specify utf8mb4.

Security

Injection
The general failure where data crosses into a position where it is interpreted as code. SQL injection, XSS, command injection, path traversal and header injection are all instances.
SQL injection
User input interpolated into a query, changing its meaning. Defence: prepared statements — never escaping, never sanitising.
XSS
User input rendered as HTML, so it becomes markup or script running with the viewer's privileges. Defence: escape on output, per context.
CSRF
A third-party site causing an authenticated user's browser to submit a request. Defence: an unpredictable token bound to the session, plus SameSite cookies. Lesson 0023.
Authentication
Who are you? Login, sessions, tokens, password verification. Status code 401.
Authorization
Are you allowed to do this? Ownership, roles, permissions. Status code 403.
IDOR
Insecure Direct Object Reference — exposing a record's id and not verifying the requester may have it. Change the number, read someone else's data. Fixed by checking ownership on every request, never by hiding the id.
Allowlist
Permitting only known-good values. Always preferable to a denylist, which fails against anything its author did not anticipate.
Information disclosure
Revealing more than intended — including that a record exists. Why GitHub returns 404, not 403, for private repositories you cannot see.

The wider ecosystem

SSR
Server-Side Rendering — HTML built per request on the server. What PHP has always done.
SSG
Static Site Generation — HTML built at deploy time and served as files.
CSR
Client-Side Rendering — the server sends a shell and JavaScript builds the DOM in the browser.
ISR
Incremental Static Regeneration — static pages regenerated in the background after a set interval. Vercel's signature feature.
Hydration
Attaching JavaScript behaviour to server-rendered HTML in the browser, so the markup becomes interactive without being rebuilt.
Edge
Compute running in many locations physically near users, rather than in one region. Removes round trips, which usually beats optimising server time.
CDN
A network of caching servers near users. Serves cacheable responses without touching your origin at all.
Bundler
A tool producing browser-runnable artefacts from source the browser cannot run. Exists because JavaScript lost the property PHP still has: no artefact between source and execution.
Tree-shaking
Removing unused exports from a bundle. Possible only because JavaScript's import is static — which is exactly what PHP's runtime require gives up.
Hooks (WordPress)
Named events with registered callbacks — add_action, add_filter. WordPress's extensibility model, and an instance of higher-order functions.
Active Record vs Data Mapper
Two ORM philosophies. Active Record: the model knows how to persist itself (Eloquent). Data Mapper: a separate layer moves data between objects and tables (Doctrine, and therefore Shopware).
PSR
PHP Standards Recommendations from PHP-FIG. PSR-4 (autoloading) is why class files are named after their class; PSR-7 defines immutable HTTP message objects; PSR-12 is code style.
Twelve-Factor
A set of principles for deployable apps — notably config in the environment, and stateless processes. Explains much of Heroku, Vercel and Cloudflare's design.
