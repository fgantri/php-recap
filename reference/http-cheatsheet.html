HTTP Cheat Sheet

The protocol, on two printed pages.

Anatomy of a URL

https://example.com:443/notes/17?sort=desc&page=2#comments
\___/   \_________/ \_/\_______/ \______________/\_______/
scheme     host    port   path         query      fragment
schemeProtocol. Implies the default port (80 / 443).
hostWhich machine. Sent as the Host header — mandatory in HTTP/1.1.
pathWhich resource. Routing decisions are made on this.
queryAfter ?, key=value joined by &. Fills $_GET regardless of method.
fragmentAfter #. Never sent to the server. Browser-only.

Message shape

POST /notes?draft=1 HTTP/1.1     ← request line
Host: localhost:8888             ← headers
Content-Type: application/x-www-form-urlencoded
Content-Length: 24
                                 ← BLANK LINE (required)
title=Hello&body=World           ← body, exactly Content-Length bytes
HTTP/1.1 200 OK                  ← status line
Content-Type: text/html; charset=utf-8
Content-Length: 137

<!DOCTYPE html>…

Lines end \r\n. The blank line separates headers from body. Without Content-Length or Transfer-Encoding: chunked, the client cannot tell when the body ends.

Methods

MethodMeansSafeIdempotentBody
GETRead✓✓no
HEADHeaders only✓✓no
POSTSubmit; server decides✕✕yes
PUTReplace at this URL✕✓yes
PATCHPartial update✕✕yes
DELETERemove✕✓no
OPTIONSWhat's allowed here✓✓no

Safe = changes nothing. Idempotent = N times equals once, which is what makes retry safe. Never put a destructive action behind GET — crawlers and prefetchers will fire it.

Status codes worth knowing cold

CodeNameUse when
200OKSuccess with a body
201CreatedA resource now exists — include Location
204No ContentSuccess, deliberately no body
301Moved PermanentlyCached aggressively — hard to undo. Be sure
302FoundTemporary. What post-redirect-get uses
303See OtherStrictly correct for redirect-after-POST
304Not ModifiedCached copy still valid; no body sent
400Bad RequestMalformed — syntax, unparseable
401UnauthorizedActually means unauthenticated
403ForbiddenAuthenticated, still not allowed
404Not FoundNo resource — also the honest answer when existence is sensitive
405Method Not AllowedPath exists, verb doesn't. Must send Allow
409ConflictClashes with current state
422Unprocessable ContentParsed fine, failed validation
429Too Many RequestsRate limited — send Retry-After
500Internal Server ErrorWe broke
502Bad GatewayProxy got nothing usable from upstream — PHP-FPM is down
503Service UnavailableDown or overloaded, temporarily
504Gateway TimeoutProxy waited too long — your PHP is slow or hung

The rule: 4xx = the request was wrong. 5xx = we were wrong. Returning 200 with "not found" in the body is a real bug — crawlers index it, monitoring never alerts.

Headers you will actually use

HeaderDirectionPurpose
Host→Which site. Mandatory. Enables virtual hosting
Content-Type↔How to parse the body. Always add ; charset=utf-8 on text
Content-Length↔Bytes, not characters. Use strlen()
Accept→What the client wants back — content negotiation
Cookie / Set-Cookie↔The state workaround for a stateless protocol
Location←Where to go, with a 3xx or a 201
Allow←Permitted methods. Required with 405
Cache-Control←no-store, max-age=3600, private, public
ETag / If-None-Match↔Content fingerprint → 304 when unchanged
Last-Modified / If-Modified-Since↔Timestamp version of the same
Authorization→Bearer <token>, Basic <base64>
X-Forwarded-For→Real client IP behind a proxy. Spoofable — trust only from your own proxy
Content-Security-Policy←Restricts what the page may load or execute. Defence in depth against XSS

Headers in PHP

Request header User-Agent$_SERVER['HTTP_USER_AGENT']
Request header X-Api-Key$_SERVER['HTTP_X_API_KEY']
Method / URI / queryREQUEST_METHOD, REQUEST_URI, QUERY_STRING
Send a headerheader('Content-Type: application/json');
Set the statushttp_response_code(404);

The rule: HTTP_ + name uppercased, dashes to underscores — a CGI convention from 1993. Headers must be sent before any output; a single stray byte locks them, which is why PHP-only files omit the closing ?>.

Talking HTTP without a browser

curl -i URL                       # response with headers
curl -I URL                       # HEAD — headers only
curl -v URL                       # show the request too
curl -X POST -d 'a=1&b=2' URL     # form body
curl -H 'Accept: application/json' URL
curl --path-as-is URL             # don't normalise ../ — needed for traversal tests

printf 'GET / HTTP/1.1\r\nHost: x\r\nConnection: close\r\n\r\n' | nc HOST PORT

exec 3<>/dev/tcp/example.com/80   # bash can open a socket directly
printf 'GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n' >&3
