An HTTP Server From Raw Sockets

No framework, no library, no php -S. Roughly 150 lines that accept TCP connections, parse HTTP by hand, and serve a real directory to a real browser.

~2 hoursUses lessons 0001–0007Portfolio piece

The skeleton

Enough to get you moving; the rest is yours. Type it, don't paste it.

01-http-server/server.php
<?php

$host = $argv[1] ?? '127.0.0.1';
$port = (int) ($argv[2] ?? 8888);
$root = realpath(__DIR__ . '/public');

$server = @stream_socket_server("tcp://$host:$port", $errno, $errstr);

if (! $server) {
    fwrite(STDERR, "Cannot bind $host:$port — $errstr ($errno)\n");
    exit(1);                        // non-zero: the shell must know we failed
}

fwrite(STDOUT, "Serving $root on http://$host:$port\n");

while ($conn = @stream_socket_accept($server, -1)) {
    $started = microtime(true);

    $request  = readRequest($conn);
    $response = handle($request, $root);

    sendResponse($conn, $response, $request['method'] === 'HEAD');
    fclose($conn);

    logLine($request, $response, microtime(true) - $started);
}

Write readRequest, handle, sendResponse and logLine yourself. Some guidance on the two that have traps in them:

readRequest — where malformed input arrives

Read up to the blank line, then split on \r\n. The first line gives you method, target and version. Every line after it is Name: value. Two things will bite you:

  • A header value may itself contain a colon (Host: localhost:8888). Split on the first colon only.
  • A client can disconnect mid-request, or send nonsense. Return a structure that says "malformed" and answer 400 rather than letting PHP emit a warning into your response body.

handle — where the security bug lives

This is the part that matters most. The naive version:

// DO NOT SHIP THIS
$file = $root . $path;
if (file_exists($file)) { return file_get_contents($file); }

Request /../../../../etc/passwd and you have handed over the machine's user list. Worse, if this were your notes app you would be handing over .env.

The correct defence — resolve, then verify

Do not sanitise the input by stripping ... That is defeated by %2e%2e, by ....//, by encoded slashes, and by symlinks. Instead, let the filesystem resolve the path completely and then check where it landed:

$candidate = realpath($root . '/' . ltrim($path, '/'));

if ($candidate === false || ! str_starts_with($candidate, $root . DIRECTORY_SEPARATOR)) {
    return notFound();     // outside the root — treat as missing, don't explain
}

realpath() resolves .., . and symlinks and returns the true absolute path, or false if nothing is there. Comparing the result to the root is the check — and note the trailing separator, without which a sibling directory named public-backup would pass.

Answer 404, not 403. Telling an attacker "that exists but you may not have it" is free information, and Lesson 0022 returns to exactly this trade-off.

MIME types

The browser needs to be told what it is receiving. Get this wrong and CSS arrives as plain text and is ignored — silently, with no error anywhere. Map by extension, and default to application/octet-stream:

$types = [
    'html' => 'text/html; charset=utf-8',
    'css'  => 'text/css',
    'js'   => 'text/javascript',
    'json' => 'application/json',
    'png'  => 'image/png',
    'jpg'  => 'image/jpeg',
    'svg'  => 'image/svg+xml',
];

Acceptance tests

Put some files in public/ — an index.html, a stylesheet, an image — then work down this list. Every one should behave as stated before you tag the milestone.

php server.php &                                  # start it

curl -i http://127.0.0.1:8888/                    # 200, text/html
curl -i http://127.0.0.1:8888/style.css           # 200, text/css
curl -i http://127.0.0.1:8888/nope.html           # 404 + an HTML body
curl -I http://127.0.0.1:8888/                    # HEAD: headers only, no body
curl -i -X DELETE http://127.0.0.1:8888/          # 405, with an Allow header
curl -i 'http://127.0.0.1:8888/?a=1&b=2'          # query ignored for routing
curl -i --path-as-is http://127.0.0.1:8888/../../../etc/passwd   # 404, NOT the file
curl -i http://127.0.0.1:8888/%2e%2e/%2e%2e/etc/passwd           # 404 as well

# and the honest one — no client library at all
printf 'GET / HTTP/1.1\r\nHost: x\r\n\r\n' | nc 127.0.0.1 8888
--path-as-is matters

Without that flag, curl helpfully normalises ../ out of the URL before sending it, so your server never sees the attack and you conclude you are safe. You are testing curl, not your code. The %2e%2e variant is the one a real attacker sends anyway — percent-encoded, so no intermediary normalises it.

Stretch goals

Only if you have time and appetite. Each one is a real feature of real servers, and each maps onto something you'll meet later.

Keep-alive

Honour Connection: keep-alive: loop reading further requests on the same connection instead of closing. You'll need to read exactly Content-Length bytes and not one more. This is the optimisation HTTP/1.1 was built around.

Fork per connection

pcntl_fork() after accept(), handle in the child, exit. Suddenly a sleep(5) in one request stops blocking the others. About ten lines, and it makes the worker-pool idea from Lesson 0004 concrete.

Conditional requests

Send Last-Modified; when a request carries If-Modified-Since and the file hasn't changed, reply 304 with no body. You have implemented HTTP caching — the mechanism behind every CDN.

Directory listing

When a directory has no index.html, generate a listing. Then escape the filenames with htmlspecialchars() — a file named <script>.txt is a live XSS vector, and Lesson 0013 explains exactly why.

Stuck is expected. Ask me anything — "my Content-Length is off by one", "why does Chrome hang but curl works", "is my traversal check actually safe?". That last one is worth asking even if you're confident; it is exactly the kind of code where confidence and correctness come apart.
