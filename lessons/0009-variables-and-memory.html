Variables, Types, Memory

Your course said a variable is "a name bound to a value in memory". True — and the binding is cleverer than that, in a way that decides whether passing an array to a function costs nothing or costs everything.

40 minutesWin: why copying a big array is free

Here is a question that separates people who use PHP from people who understand it. You have an array of 100,000 rows from a database. You write $copy = $rows;. How much memory did that use?

The answer is almost none — until you touch $copy. Today is about why.

The symbol table and the zval

A PHP variable is two things: an entry in the symbol table (a hash map from name to a slot) and a zval — a small container holding a type tag and a value.

Simple values — integers, floats, booleans, null — live directly inside the zval. Larger values — strings, arrays, objects — live elsewhere, and the zval holds a pointer to them plus a reference count.

Foundation — Copy-on-write, and the one rule that follows

Assignment does not copy the data. It copies the pointer and increments the refcount. Both names now point at one array.

The copy happens only when one of them is modified — at that moment PHP sees refcount > 1, duplicates the data, and lets the writer change its own copy. This is copy-on-write, and it is why PHP can pass big arrays around freely.

The rule it gives you: reading is free, writing is not. A function that receives a large array and only reads it costs nothing. The same function with one innocuous $rows[] = $x; in it silently duplicates the entire structure. When a script's memory usage doubles for no visible reason, this is nearly always why.

Objects break the pattern — deliberately

This is the exception that causes real bugs, so it's worth stating precisely.

$a = ['x' => 1];
$b = $a;
$b['x'] = 99;
echo $a['x'];        // 1  — arrays copy on write

$a = new stdClass;
$a->x = 1;
$b = $a;
$b->x = 99;
echo $a->x;             // 99 — objects are handles

An object variable holds a handle — an identifier for an object in the object store. Copying the variable copies the handle, and both handles refer to the same object. There is no copy-on-write, because nothing was ever conceptually copied.

Say it precisely, because the folklore is wrong

People say "objects are passed by reference in PHP". They are not, and the difference is testable:

function reassign($o) { $o = new stdClass; $o->x = 'new'; }
function mutate($o)   { $o->x = 'changed'; }

$obj = new stdClass; $obj->x = 'original';

reassign($obj); echo $obj->x;   // original — the handle was copied
mutate($obj);   echo $obj->x;   // changed  — same object behind both handles

The handle is passed by value. You can mutate what it points at; you cannot make the caller's variable point somewhere else. That is exactly Java's and JavaScript's model too, and getting the wording right here is a small mark of someone who actually knows the runtime.

Dynamic typing, and the modern escape from it

Your course flagged the hazard: a variable has no declared type, so a value of the wrong type travels silently until something downstream misbehaves — and Chapter 14's fetch() returning false instead of an array is exactly that failure.

Modern PHP lets you close the gap. Put this at the top of every PHP file you write from now on:

declare(strict_types=1);

Bridge — this is the same argument as TypeScript

PHP's type declarations are enforced at runtime: the check happens when the call is made. TypeScript's are enforced at compile time and erased entirely — at runtime, a TypeScript function will happily receive a string where a number was declared, because the compiler is gone.

Two genuinely different bets. PHP catches everything but only when the line executes. TypeScript catches at build time but only what it can prove, and lies to you the moment data arrives from an API. Tools like Zod exist precisely to add PHP-style runtime checking back to TypeScript at the boundaries — which tells you something about which problem is harder.

Strings, and one number worth knowing

Install checkpoint 2 — three packages

Run php -m | grep -i mbstring. Nothing? Correct — you installed only php-cli in Lesson 0000. Time for rung 2:

sudo apt install -y php-mbstring php-curl php-sqlite3

php-mbstring — the multi-byte string functions used immediately below. Without it, mb_strlen() is undefined and any attempt to cut a string safely will split characters in half.
php-curl — outbound HTTP, so your server can be a client. Needed from Project 3 onward.
php-sqlite3 — a database with no server, no port and no password. Lesson 0016 explains why you may not need MySQL at all.

Confirm with php -m | grep -E 'mbstring|curl|sqlite' — three lines where there were none. You just watched a capability appear, which is exactly what a bundle hides from you.

PHP strings are byte arrays with a length, not null-terminated. strlen() counts bytes; mb_strlen() counts characters.

strlen('café');      // 5 — é is two bytes in UTF-8
mb_strlen('café');   // 4

This matters more than it looks. Content-Length in Project 1 must be strlen — HTTP counts bytes. A VARCHAR(255) column and a substr() truncation disagree about "255" unless you are careful. And splitting a multi-byte character in half produces the mojibake you have seen on badly built sites.
