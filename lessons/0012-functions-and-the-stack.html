#2 {main}
  thrown in /var/www/app/controllers/note.php on line 9
Foundation — How to read it in the right order

1. The last line, not the first. thrown in … note.php on line 9 is where execution actually died. That is where you look.

2. The message, precisely. "Call to a member function query() on null" says $db was null — not missing, not the wrong class. Null. So something that should have assigned it did not.

3. The frames, top-down, to answer "how did I get here". #0 is the most recent caller, {main} is the file the request entered through. Reading upward from {main} gives you the path: index.php required router.php, which required the controller.

4. Find the first frame in your code. In a framework trace, most frames belong to the vendor directory. The first line under your own namespace is almost always the real culprit — the framework is usually just reporting your mistake faithfully.

For this specific trace the diagnosis is your course's Chapter 14 bug: index.php required the router before creating $db, so by the time the controller ran, the variable did not exist.

Scope: the restriction that is a feature

Your course put it well — a function that reaches out and grabs whatever is lying around cannot be understood in isolation. PHP enforces this harder than most languages: an inner function cannot see the enclosing scope at all, not even for reading.

$author = 'Andy Weir';

// Undefined variable $author — PHP does not capture automatically
$byAuthor = function ($book) {
    return $book['author'] === $author;
};

// Explicit capture, by value — a snapshot taken at definition time
$byAuthor = function ($book) use ($author) {
    return $book['author'] === $author;
};

// Arrow function — captures automatically, by value, single expression only
$byAuthor = fn ($book) => $book['author'] === $author;
The capture-by-value gotcha 
$multiplier = 2;
$double = fn ($n) => $n * $multiplier;
$multiplier = 10;

echo $double(5);    // 10, not 50

The closure captured the value 2 at the moment it was defined, not a live link to the variable. This is usually what you want — it makes closures predictable — but it surprises people building closures inside loops. use (&$x) captures by reference if you genuinely need the live link, which you rarely do.

Higher-order functions, built by hand

Your course built filter and then replaced it with array_filter. Build the other two now — the three together cover most of what you'll ever do to a collection.

function map($items, $fn) {
    $out = [];
    foreach ($items as $item) { $out[] = $fn($item); }
    return $out;
}

function reduce($items, $fn, $carry = null) {
    foreach ($items as $item) { $carry = $fn($carry, $item); }
    return $carry;
}
VerbShapeUse when
mapn in → n outTransforming each element
filtern in → ≤n outSelecting a subset
reducen in → 1 outCollapsing to a single value — sum, max, grouping

PHP's argument order is inconsistent between them (array_map($fn, $array) but array_filter($array, $fn)) for historical reasons. Everyone looks it up. Do not feel bad about looking it up.

Bridge — callbacks are the whole architecture of everything you named

Middleware is a chain of callbacks, each handed the request and the next handler. WordPress hooks are callbacks registered against named events — add_action and add_filter are literally this. React components are functions passed to a renderer that decides when to call them. Laravel's routes are callbacks registered against URIs — exactly what you'll build in the next lesson. Event listeners, promises, array methods — all the same shape.

The unifying idea your course named: the higher-order function owns the mechanism, the caller owns the policy. Once you can see that split, framework source code stops being intimidating, because nearly all of it is that pattern applied at different scales.

Primary source for this lesson PHP Manual — Anonymous functions for closures and use semantics, and arrow functions for the auto-capture rules.

Then first-class callable syntax (PHP 8.1) — strlen(...) turns any function into a value, which makes higher-order code substantially cleaner than the string-name approach in older code.
Ask your teacher. Ask me to "break my code deliberately in three different ways and let me read the traces" — trace-reading is a skill that only comes from repetition, and doing it under no time pressure now is worth a lot on Monday.
