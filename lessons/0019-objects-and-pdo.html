Objects, Classes, PDO

A class is a blueprint; an instance is a house built from it. Your course said that well. What it left out is the modern syntax — and three PDO settings that decide whether your authorization checks work.

50 minutesWin: blueprint vs instance, and a correctly configured connection

The class, written the way you'd write it in 2026

Your course's Person class is correct and dated. Here is the same idea with everything PHP has added since:

The 2015 way

class Note
{
    public $id;
    public $body;

    public function __construct($id, $body)
    {
        $this->id = $id;
        $this->body = $body;
    }
}

The 2026 way

final class Note
{
    public function __construct(
        public readonly int $id,
        public readonly string $body,
    ) {}
}
FeatureSinceBuys you
Constructor promotion8.0Declare, type and assign a property in one place
readonly8.1Assignable once, in the constructor. Immutability with no boilerplate
final5.0Nobody can subclass and change behaviour under you
Typed properties7.4Wrong types fail at assignment, not three frames later
Named arguments8.0new Note(id: 1, body: 'x') — order-free, self-documenting
Enums8.1A fixed set of values the type system enforces
Foundation — Why visibility exists, stated usefully

Your course said public everywhere is fine while learning, and flagged it as a temporary simplification. Here is the sharp version of why:

Every public property is a permanent promise. Once outside code can read $note->body, you can never rename it, change its type, or compute it differently without breaking every caller. A class where everything is public has no internals — its entire shape is its API.

private is not about secrecy. It is about reserving the right to change your mind. That is the whole of encapsulation, and it is the same argument as the document root in Lesson 0007: expose a deliberate, small surface.

Enums, which your course predates

enum NoteStatus: string
{
    case Draft     = 'draft';
    case Published = 'published';
    case Archived  = 'archived';

    public function isVisible(): bool
    {
        return $this === self::Published;
    }
}

$status = NoteStatus::from($row['status']);   // throws on an unknown value
$status = NoteStatus::tryFrom($bad) ?? NoteStatus::Draft;

Compare with const STATUS_DRAFT = 'draft': a constant is a suggestion — nothing stops $note->status = 'drft'. An enum is a type, so a function declaring NoteStatus $status cannot receive anything else. Use enums for every fixed set of values.

Connecting to MySQL

$dsn = 'mysql:host=localhost;port=3306;dbname=myapp;charset=utf8mb4';

Key–value pairs joined by semicolons — the same shape as a query string, a header set, an environment. charset=utf8mb4 is not optional: MySQL's utf8 stores three bytes per character and silently mangles emoji and some CJK text.

The three options that are not optional

$pdo = new PDO($dsn, $user, $pass, [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
]);
What each one prevents

ERRMODE_EXCEPTION — without it, PDO's default is to fail silently: a broken query returns false and your code carries on with nonsense. This single line converts an entire class of silent wrongness into loud, catchable failure.

FETCH_ASSOC — the default returns every value twice, once by column name and once by numeric index. Your course noticed this and fixed it per-call; setting it once on the connection is better.

EMULATE_PREPARES => false — the important one. With emulation on (the default for MySQL), PDO builds the query string itself and every column comes back as a string. So $note['user_id'] is '1', not 1, and your course's Chapter 14 ownership check —

if ($note['user_id'] !== $currentUserId) { abort(403); }

— is '1' !== 1, which is true. The rightful owner gets a 403. Turn emulation off and MySQL prepares the statement for real, returning native integers. (If you must leave it on, cast: (int) $note['user_id'].)

Prepare, execute, fetch

$statement = $pdo->prepare('SELECT * FROM notes WHERE user_id = :uid');
$statement->execute(['uid' => $userId]);

$rows = $statement->fetchAll();   // array of rows; [] when none
$row  = $statement->fetch();      // ONE row, or FALSE when none

The three-step split looks like bureaucracy. Lesson 0020 shows it is the single most important security mechanism you will use.

fetch() returns false, and that's a type change

Your course hit this in Chapter 14: a query for a note that doesn't exist returns false, not an empty array. Dynamic typing lets that boolean travel until a view tries to use it as an array, and the error surfaces far from the cause.

Handle it at the point it occurs: if (! $note) { abort(404); } — immediately after the fetch, before anything else touches it. Errors that travel before surfacing are the expensive ones.

The Database class

src/Database.php
<?php

declare(strict_types=1);

final class Database
{
    private PDO $connection;

    public function __construct(array $config, string $user = 'root', string $pass = '')
    {
        $dsn = 'mysql:' . http_build_query($config, '', ';');

        try {
            $this->connection = new PDO($dsn, $user, $pass, [
                PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
                PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                PDO::ATTR_EMULATE_PREPARES   => false,
            ]);
        } catch (PDOException $e) {
            // the message can contain the password — never let it reach the user
            error_log('DB connection failed: ' . $e->getMessage());
            throw new RuntimeException('Database unavailable', 0, $e);
        }
    }

    public function query(string $sql, array $params = []): PDOStatement
    {
        $statement = $this->connection->prepare($sql);
        $statement->execute($params);

        return $statement;
    }
}

Three decisions worth naming. The connection is built once, in the constructor — your course's first version opened one per call, which is expensive under load. query() returns the statement, not results, so the caller chooses fetch or fetchAll. And $connection is private: nothing outside can bypass query() and issue an unprepared statement.

Foundation — __construct makes invalid objects impossible

Because the connection is established in the constructor, no Database object can exist in a half-initialised state. If construction fails, you get an exception rather than an object that will fail later, somewhere else.

That property — an object is valid from the moment it exists — is worth a great deal, and it is the main argument for doing real work in constructors rather than in an init() method someone might forget to call.

Config, pushed outward

config.php
<?php

return [
    'database' => [
        'host'    => $_ENV['DB_HOST'] ?? 'localhost',
        'port'    => $_ENV['DB_PORT'] ?? 3306,
        'dbname'  => $_ENV['DB_NAME'] ?? 'myapp',
        'charset' => 'utf8mb4',
    ],
];

A required file can return a value — $config = require 'config.php';. That is exactly how Laravel's config/ directory works, and now that layout is legible on sight.

The progression your course named is worth memorising as a chain: hardcoded value → constructor parameter → config file → environment variable. Each step pushes the value further from the code and closer to the deployment. That is Twelve-Factor factor III, and it is why .env exists.
