Development and production want opposite things, and getting this backwards is either painful or dangerous.

SettingLocalProductionWhy
display_errorsOnOffStack traces leak paths, queries, and sometimes credentials to attackers

Set them for this weekend:

php -i | grep -E '^(display_errors|error_reporting|error_log)'

# or per-run, without touching php.ini
php -d display_errors=1 -d error_reporting=E_ALL server.php
The blank white page

A completely blank page with HTTP 200 in production almost always means: a fatal error occurred, display_errors is off (correctly), and you have not looked at the log yet. It is not a mystery — it is a message delivered somewhere you are not looking.

tail -f /var/log/php8.4-fpm.log, and separately your nginx error log. Knowing which log holds the answer is most of the diagnosis, and it is the skill Lesson 0007 was setting up.

Catching properly

try {
    $db = new Database($config['database']);
} catch (PDOException $e) {
    error_log('DB connect failed: ' . $e->getMessage());   // for you
    abort(503);                                              // for the user
} finally {
    // runs either way — release locks, close handles
}
Foundation — Three rules that make error handling useful rather than decorative

1. Catch narrowly. catch (Throwable $e) around a whole controller swallows genuine bugs and turns them into a generic message. Catch the specific type you can actually do something about, at the level where you can do it.

2. Never catch and continue silently. An empty catch block is how a system develops symptoms with no cause. If you cannot handle it, let it propagate — a loud failure is far cheaper than a quiet wrong answer.

3. Two audiences, two messages. The user gets "something went wrong" plus a reference. The log gets the type, message, file, line, stack trace and request context. Merging them either leaks internals or throws away your only diagnostic.

One global handler

Rather than wrapping everything, register handlers once during bootstrap:

set_exception_handler(function (Throwable $e) {
    error_log(sprintf(
        "%s: %s in %s:%d\n%s",
        get_class($e), $e->getMessage(),
        $e->getFile(), $e->getLine(), $e->getTraceAsString()
    ));

    http_response_code(500);
    echo view('errors/500');
});

set_error_handler(function ($severity, $message, $file, $line) {
    throw new ErrorException($message, 0, $severity, $file, $line);
});

The second one is the interesting move: it promotes warnings into exceptions, so an ignorable "Undefined array key" becomes a stoppable, catchable, logged event. That single line changes a class of silent wrongness into loud failure, which is nearly always the better trade.
