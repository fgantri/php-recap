From URL to Pixels

The interview question that is actually a map of the entire industry. Every job title in web development lives at one of these nine hops.

45 minutesWin: name all nine hops, in order

You have now built two of these hops yourself. This lesson assembles the whole chain, and — more usefully — attaches a time cost to each one, because that is what turns the list into engineering judgement.

The nine hops

HopWhat happensWho owns it
1Parse the URLSplit scheme, host, port, path, query, fragment. The fragment is kept by the browser and never sent.Browser
2DNS resolutionTurn example.com into an IP. Four caches are consulted before the network is touched.DNS / Cloudflare
3TCP handshakeSYN → SYN-ACK → ACK. One full round trip before a single byte of your data moves.Kernel
4TLS handshakeCertificate, key agreement, protocol negotiation. One more round trip (TLS 1.3) or two (1.2).TLS / certificate authority
5HTTP requestThe text from Lesson 0005 goes down the socket.Browser
6Server handlingnginx matches a location, hands dynamic paths to PHP-FPM, PHP runs, the database answers.You
7HTTP responseStatus, headers, body travel back. Time to first byte is measured here.You
8Parse and buildHTML → DOM, CSS → CSSOM, combined into a render tree.Browser
9Layout, paint, compositeCompute geometry, fill pixels, hand layers to the GPU.Browser / GPU
Hops 3 and 4 are why HTTPS once felt slow: two extra round trips before any content moves. TLS 1.3 cut it to one, and 0-RTT resumption to zero for repeat visits. This is also why HTTP/3 was built on UDP — it merges the transport and crypto handshakes into a single round trip.

Where the time actually goes

Pick a scenario. The bars are milliseconds, roughly to scale, for a small dynamic page.

Latency waterfall

Read the chart, not the folklore

On a transatlantic connection, the network round trips dwarf your PHP. Shaving 20 ms off a controller is invisible when DNS, TCP and TLS have already spent 350 ms. That is why CDNs and edge caching produce speedups that no amount of code optimisation can match — they remove round trips, not milliseconds.

It is also why the advice inverts on localhost, where round trips are free and your code is the only cost. Optimising against the wrong scenario is one of the most common wastes of engineering time.

Hop 2 in detail: DNS is a cache hierarchy

"DNS turns a name into an IP" is true and hides the interesting part — that four caches are checked first, and a full lookup is rare.

Hops 8 and 9: what the browser does with your text

Your PHP output is a string. Turning it into pixels is its own pipeline, and the one part of it worth knowing cold is what blocks.

StageProducesBlocked by
Parse HTMLThe DOM treeA synchronous <script> — parsing stops dead until it downloads and runs
Parse CSSThe CSSOM treeNothing blocks parsing, but rendering waits for all of it
Render treeDOM + CSSOM, visible nodes onlyBoth of the above
LayoutGeometry — position and size of every boxRecomputed on any size change ("reflow")
PaintPixels, in layers—
CompositeLayers assembled, usually on the GPU—

This is the reason for two pieces of advice you have certainly seen without the justification: CSS goes in the <head> (rendering is blocked until CSSOM is complete, so request it as early as possible), and scripts go at the end of <body>, or carry defer (a synchronous script halts HTML parsing, because it might call document.write).

Bridge — every rendering strategy is a bet about hop 6 vs hop 8

The entire SSR/CSR/SSG argument is about where HTML gets built, and this table is the whole of it:

Classic PHP / SSR — HTML is built per request at hop 6. First paint is fast, the server does work every time. This is WordPress, Laravel, and Next.js in server mode.

SSG — HTML is built at deploy time and served as a static file. Hop 6 becomes nearly free. This is Astro, Hugo, and Next's generateStaticParams.

CSR — the server sends an empty shell plus JavaScript, and the DOM is built in hop 8 on the user's device. Fast to deploy, slow to first paint, and invisible to naive crawlers. This is a plain Vite + React SPA.

ISR / edge rendering — build statically, but regenerate in the background, at a location near the user. Vercel and Cloudflare's whole product line is this bet.

None is correct in general. When you can say which hop each one moves work to, and what that costs, you can actually choose — which is precisely the fluency this weekend is for.
