Routing and the Front Controller

Your course built a router that matches whole URIs. Today you add the two things that make it a real one: dynamic segments and method matching — which is to say, you build Laravel's routing layer in about forty lines.

50 minutesWin: one entry point, any URL

You already know the shape from Chapter 09: one entry point, read the URI, look it up, require a controller. And you know from Lesson 0007 exactly what makes it possible — nginx's try_files falling through to index.php when no file matches. The two halves now meet.

The limitation to remove

Your course was explicit about it: "Your router matches whole URIs, so dynamic segments like /notes/17 are not possible yet. Use the query string instead."

That workaround gave you /note?id=17. It works. It is also why your URLs look like 2004. Fixing it needs one idea: compile each route pattern into a regular expression with a capture group.

'/notes/{id}'   →   '#^/notes/(?P<id>[^/]+)$#'

Read the pieces: #…# are delimiters, ^ and $ anchor to the whole string (without them /evil/notes/17 would match), (?P<id>…) is a named capture group, and [^/]+ means "one or more characters that are not a slash" — so {id} matches one segment, never two.

Foundation — Why order matters, and the 405 nobody implements

First match wins, so specific routes must be registered before general ones. /notes/create has to come before /notes/{id}, or the literal word "create" gets captured as an id. Laravel, Symfony and Express all behave this way, and it is a routine source of confusion.

Path matched but method didn't? That is 405 Method Not Allowed, not 404. It must carry an Allow header listing the acceptable verbs. Almost no hand-rolled router does this and it costs nothing — collect the methods that matched the path, and if the set is non-empty but your verb isn't in it, answer 405.

The Router class

src/Router.php
<?php

class Router
{
    private array $routes = [];

    public function add(string $method, string $path, string $controller): void
    {
        $pattern = preg_replace(
            '#\{(\w+)\}#',
            '(?P<$1>[^/]+)',
            $path
        );

        $this->routes[] = [
            'method'     => $method,
            'pattern'    => "#^{$pattern}$#",
            'controller' => $controller,
        ];
    }

    public function get(string $p, string $c): void  { $this->add('GET', $p, $c); }
    public function post(string $p, string $c): void { $this->add('POST', $p, $c); }

    public function dispatch(string $method, string $uri): void
    {
        $path    = parse_url($uri, PHP_URL_PATH) ?: '/';
        $allowed = [];

        foreach ($this->routes as $route) {
            if (! preg_match($route['pattern'], $path, $matches)) {
                continue;
            }

            if ($route['method'] !== $method) {
                $allowed[] = $route['method'];
                continue;
            }

            // named groups only — drop the numeric duplicates
            $params = array_filter(
                $matches,
                'is_string',
                ARRAY_FILTER_USE_KEY
            );

            require $route['controller'];
            return;
        }

        if ($allowed) {
            header('Allow: ' . implode(', ', array_unique($allowed)));
            abort(405);
        }

        abort(404);
    }
}
$router = new Router();

$router->get('/',              'controllers/index.php');
$router->get('/notes',         'controllers/notes/index.php');
$router->get('/notes/create',  'controllers/notes/create.php');  // before {id}!
$router->get('/notes/{id}',     'controllers/notes/show.php');
$router->post('/notes',        'controllers/notes/store.php');

$router->dispatch($_SERVER['REQUEST_METHOD'], $_SERVER['REQUEST_URI']);
What just changed

Compare with your course's version. The route table went from '/about' => 'controllers/about.php' to a list of objects with a method, a compiled pattern and a handler. That is structurally what Laravel's routes/web.php is — Route::get('/notes/{id}', ...) is this exact call, and Illuminate\Routing\Router is this class with caching, middleware, model binding and named routes added.

You have not built a toy. You have built the core and left off the features.

The bootstrap, and what belongs in it

Your course's Chapter 14 hit a real bug: the controller needed $db, but index.php required the router before creating it. The fix was ordering — and the ordering is the bootstrap.

public/index.php
<?php

declare(strict_types=1);

require __DIR__ . '/../src/functions.php';   // 1. helpers
require __DIR__ . '/../src/Database.php';
require __DIR__ . '/../src/Router.php';

$config = require __DIR__ . '/../config.php';  // 2. configuration

$db = new Database($config['database']);        // 3. shared services

require __DIR__ . '/../routes.php';            // 4. register routes

$router->dispatch(                                // 5. dispatch
    $_SERVER['REQUEST_METHOD'],
    $_SERVER['REQUEST_URI']
);

Helpers, config, services, routes, dispatch. Every framework's bootstrap is these five steps in this order, and knowing that means you can read an unfamiliar index.php in thirty seconds.

The honest limitation — and what fixes it

$db reaching controllers through shared scope works and does not scale. A controller depends on a variable it never declares, so you cannot tell what it needs by reading it, and you cannot test it without building the whole world.

The fix is dependency injection: a component states its needs as constructor parameters and a container supplies them. Project 4 builds a small one. Having felt the limitation first is exactly why Laravel's service container will make sense rather than seeming like ceremony.

Bridge — three ways the industry declares routes

A route file — Laravel's routes/web.php, Express's app.get(...). Everything in one place; easy to audit, and it drifts from the controllers.

Attributes/decorators — Symfony's #[Route('/notes/{id}')] above the method. The route lives next to what it does; you lose the single overview (hence bin/console debug:router).

File-system routing — Next.js's app/notes/[id]/page.tsx, SvelteKit, Astro. The directory tree is the route table. Zero configuration, and the URL structure is now coupled to your folder layout.

All three compile down to what you just wrote: patterns, in order, matched against a path. Next's [id] is your {id} — the same capture group with different punctuation.

Primary source for this lesson Symfony's HttpKernel component — the request→response engine underneath Symfony, Drupal and Shopware. Read the "Resolve the Controller" and "Handle the Request" sections; it is your dispatch() method written properly, and it is small enough to read.

For the regex itself: PCRE named subpatterns.
