When Data Becomes Code

The most important lesson of the weekend. Everything else can be got wrong and fixed later; this one destroys your database or hands over every user record.

55 minutesWin: run the attack, then close it

Your course put the principle first and it is the right one: assume every piece of user input is hostile until you have handled it as such. Today you are the attacker.

Why it works at all

Foundation — The trust boundary was crossed inside your PHP

Your SQL is a string. The user's input is a string. When you interpolate one into the other, MySQL receives one piece of text and has no way whatsoever to tell which characters you wrote and which a stranger supplied.

The database is behaving perfectly. It parses the text it was given and executes the statements it finds. The failure happened in your PHP, before MySQL ever saw anything.

This is the identical failure as XSS in Lesson 0013, as command injection, as path traversal in Lesson 0002, and as the shell quoting in Lesson 0003. One shape, five names: data crossing into a position where it is interpreted as code.

Why separation defeats it

The fix is not to clean the input. It is to send the query and the values separately.

So a user submitting 1; DROP TABLE users causes the database to look for a note whose id equals the literal string 1; DROP TABLE users. It finds nothing. It returns an empty result. Nothing is dropped, because there was never a second statement — only a value that happened to contain a semicolon.

Why this is categorically stronger than escaping

Escaping tries to neutralise dangerous characters, and therefore depends on getting every case right across every character set, every encoding, and every context. It has failed repeatedly and historically — addslashes was defeated by multi-byte character sets in a well-known 2006 attack.

Separation removes the possibility that user data is ever interpreted as structure. There is no clever payload, because the payload never reaches a parser. That difference — eliminating a category rather than filtering instances — is what makes a defence trustworthy.

The one real limitation

Placeholders bind values, never identifiers. You cannot parameterise a table name, a column name, or a sort direction:

// impossible — this is not a value slot
$db->query('SELECT * FROM notes ORDER BY ? ?', [$column, $direction]);

// correct: an explicit allowlist of things YOU wrote
$sortable = ['id', 'created_at', 'body'];

$column    = in_array($_GET['sort'] ?? '', $sortable, true) ? $_GET['sort'] : 'id';
$direction = ($_GET['dir'] ?? '') === 'desc' ? 'DESC' : 'ASC';

$db->query("SELECT * FROM notes ORDER BY {$column} {$direction}");

That interpolation is safe because the variables can only ever hold one of a handful of strings you wrote. Note the true third argument to in_array — without it the comparison is loose, and loose comparison in a security check is how allowlists get bypassed.

Never validate an identifier with a regex like /^[a-z_]+$/. It permits column names that don't exist, leaks schema information through error messages, and grows holes as requirements change. Allowlist the finite set.

Do it for real

The lab is a simulation. Reproduce it against your actual MariaDB — the muscle memory of watching a real table vanish is worth ten minutes.

mysql -u root myapp
CREATE TABLE victims (id INT PRIMARY KEY, name VARCHAR(50));
INSERT INTO victims VALUES (1,'a'), (2,'b');
exit
inject.php
<?php
$pdo = new PDO('mysql:host=localhost;dbname=myapp;charset=utf8mb4', 'root', '', [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
]);

$id = $argv[1] ?? '1';

$sql = "SELECT * FROM victims WHERE id = $id";   // VULNERABLE
echo "SQL: $sql\n";
var_dump($pdo->query($sql)->fetchAll());
php inject.php 1
php inject.php "1 OR 1=1"          # every row
php inject.php "1; DROP TABLE victims"

mysql -u root myapp -e 'SELECT * FROM victims;'   # gone?

Then rewrite it with prepare / execute and run the same payloads. Do this on your own machine, on a throwaway table, and nowhere else. Running these against a system you do not own is a crime in essentially every jurisdiction.
